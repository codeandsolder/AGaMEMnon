# AGRV2K bitstream format

AGaMEMnon reads and writes two fabric-image formats: a compressed `.bin` used by
flash workflows and an uncompressed image convenient for SRAM loading and
inspection.

## Compressed `.bin`

A compressed image is an eight-byte header followed by an LZW stream:

```text
offset  size  field
0       4     DEVICE_ID = 0x40200001, bytes 40 20 00 01
4       4     max_index = 0x0000ffff, bytes 00 00 ff ff
8       ...   variable-width LZW stream
```

There is no separate file-level CRC. Integrity is checked after decompression.

### LZW parameters

- literals: codes 0-255;
- CLEAR: 256;
- first dictionary code: 258;
- no end-of-information code;
- initial width: 9 bits;
- dictionary reset when the next code reaches 1024;
- MSB-first bit packing;
- final byte padded with zero bits.

The stream decodes to exactly 99,936 bytes. The implementation is in
`agamemnon/engine/lzw_codec.py`.

## Uncompressed image

The SRAM form is the same eight-byte header followed directly by the 99,936-byte
raw configuration, for 99,944 bytes total.

The raw configuration is:

| Range | Contents |
|---|---|
| `[0:164]` | global/configuration-chain preamble |
| `[164:99932]` | tile and routing configuration |
| `[99932:99936]` | CRC |

The preamble is generated by `engine/preamble.py`. It contains fixed records plus
the selected clock/PLL profile; it is not copied from the old vendor canvas.

The CRC is CRC-32/BZIP2:

```text
poly     0x04C11DB7
init     0xffffffff
xorout   0xffffffff
refin    false
refout   false
```

It covers:

```text
header[0:8] + raw[0:99932]
```

and is stored big-endian in the final four raw bytes.

On the L48 reference part a bad CRC produces `ERR_CRC`; a successfully accepted
configuration reports `FCB_STAT = 0x000f0002`.

## Mapping configuration bits

The `.agasc` database currently names about 300k distinct physical
configuration bits across 210 tile coordinates. The exact count changes as new
fields are decoded.

A configuration coordinate `(top_wl, top_bl)` maps into the raw image by its
rank among the used bit-lines for that word-line:

```text
rank = index of top_bl in sorted_used_bit_lines[top_wl]
byte = 116 * top_wl + rank // 8 + 164
bit  = 7 - (rank % 8)
```

Unused bit-line gaps are omitted from storage. LUT truth tables use complemented
SRAM polarity. See `agamemnon/engine/physmap.py`.

## Routing selectors

Most configurable routing edges are selected by a two-hot code in an RMUX or
IMUX block.

Release builds use selector encodings from:

- exact conflict-free physical observations;
- tile-relative patterns for which all observations agree;
- separately recovered special-block/MCU boundary tables.

Ambiguous selectors are rejected rather than guessed. The router and bitgen use
the same accepted selector set so an edge should not route successfully and
then fail only because bitgen cannot encode it.

`--research-unsafe` can use broader recovered or predicted selector data. It
records what it used in a sidecar. Completely unresolved selectors are still
rejected.

One important special case: a vendor route containing

```text
IMUX -> alta_slice -> OMUX
```

passes through an actual LUT. It is not a free routing edge. AGaMEMnon requires
the LUT to be instantiated/configured instead of treating that segment as a
wire. The first full AHB-read route exposed this when three data lanes were
stuck until the LUT buffers were modeled properly.

## Design-neutral base image

Normal builds start from a design-neutral image generated by
`agamemnon/engine/default_frame.py` from public data tables. Its body is
byte-identical to the decoded reference canvas.

`agamemnon/chipdb/fabric_default.bin` is still shipped as a decoding/differential
reference and can be selected explicitly with `AGAMEMNON_BASELINE`, but its
stored CRC is stale and it is not directly loadable.

Bitgen then:

1. writes the generated preamble;
2. clears design-dependent logic/routing fields;
3. applies the placed/routed design and supported hard-block settings;
4. recalculates the CRC.

See [FABRIC_DEFAULT_CANVAS.md](FABRIC_DEFAULT_CANVAS.md) for the detailed base
image archaeology.

## `.agasc`

`.agasc` is a lossless text representation of the raw configuration. Known
features are named; asserted bits without a known semantic name are kept as raw
records.

Example:

```text
.agasc 1
.device 0x40200001
.max_index 0x0000ffff
.raw_length 99936
.crc auto
.tile 10 4
+CFG_LUT[0]
+CFG_OMUX0[2]
.end
.raw 000080 ff00
```

The assembler rejects unknown/duplicate features, overlapping raw ranges and raw
writes that collide with named bits.

`.crc auto` recalculates the CRC. `.crc preserve` is mainly useful when studying
intentionally broken images.

```bash
agamemnon to-agasc fabric.bin -o fabric.agasc
agamemnon from-agasc fabric.agasc -o rebuilt.bin
agamemnon from-agasc fabric.agasc --uncompressed -o rebuilt-raw.bin
```

## Useful commands

```bash
# Routed JSON -> uncompressed + compressed images
agamemnon pack routed.json design.bin

# Image -> raw configuration
agamemnon unpack design.bin.comp -o raw.img
agamemnon decode design.bin.comp -o raw.img

# Raw configuration -> compressed image
agamemnon encode raw.img -o design.bin.comp

# Change one LUT without rerouting
agamemnon edit-lut design.bin --le 20,12,1 --init 0x96e9 -o edited.bin

# Inspect and compare images
agamemnon explain design.bin
agamemnon diff old.bin new.bin
```

`explain --json` and `diff --json` keep both the source-file hash and the
canonical decoded-image hash, so compressed and uncompressed containers do not
lose their original provenance during inspection.

## Flash boot

At power-on the boot ROM gets the fabric pointer from option bytes. In the
compressed layout it runs the configured decompressor, expands the raw
99,936-byte image, and streams it into the FCB.

The supported persistent workflow replaces the compressed image at the existing
pointer while preserving the decompressor. See [PROGRAMMING.md](PROGRAMMING.md)
and [flashboot/FLASH_LAYOUT.md](flashboot/FLASH_LAYOUT.md).

For current feature support and known hardware failures, see
[STATUS.md](STATUS.md).
